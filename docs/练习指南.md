# 练习指南：三步走完「调优闭环」

> 三个练习对应使用这个平台的三层能力：①看懂 agent 怎么跑（架构理解）②评 case 做归因（评估方法论）③改资产验证提升（迭代闭环）。
> 练习三需要真跑模式（.env.local 配置 DeepSeek API Key）。

---

## 练习一：跑一个口径，看懂 ReAct 决策链路（约 15 分钟）

**做什么**
1. 打开「运行台」，选：竞对C·食达汇 × 上海 × 半熟调理，Prompt 版本选 `baseline（调优起点）`
2. 点「开始运行」，观察决策链路逐步展开：T1 探测 → 路由到 T4（为什么不是 T2？）→ T5 对齐 → T6 理由 → Validator
3. 展开每一步看输入输出。重点看 T5：边界商品（如「川香腌制麻辣牛肉片」）被映射到了哪个类目？
4. 再分别跑竞对A（有销量）和竞对B（仅库存）各一个口径，对比路由差异

**自测问题**
- 为什么竞对C走 T4 多因子评分而不是 T2？（T1 探测到 coverage=none，动态路由——三策略瀑布的 agent 化）
- 为什么所有数值都来自工具返回而不是模型计算？（数值确定性交给代码，幻觉的破坏面被锁死在可评审的语义层）
- Validator 校验哪三件事？为什么自由文本理由里的数字它管不住？（管不住 E3——这正是理由模板化的动机）

## 练习二：评审 20 条 case，建立归因思维（约 45 分钟）

**做什么**
1. 打开「抽样队列」，生成 20 条评审任务（观察分层：竞对×品类轮转、低置信度优先）
2. 逐条评审。对每条 case 先自己判断，再看左侧「自动评测（judge 初筛）」是否一致
3. 必须找到并正确标注这两类 case：
   - 一条 **E3 理由幻觉**：打开决策链路里的策略工具输出，核对理由中的数字（高亮显示）与工具返回是否一致——你会找到一条「理由写 8000+ 件、工具返回 2400 件」的 case
   - 一条 **E1 类目映射错误**：开「深检模式」看真值比对，边界商品是重灾区
4. 打开「仪表盘」看你的标注汇总进了错误分布

**自测问题**
- E1-E5 各自的责任方和处理方向（E1→T5 语义、E2→策略/数据、E3→T6 生成、E4→工程、E5→召回）
- 为什么说「评 case 最大的价值不是打分，是归因」？（责任方不同，处理路径完全不同——E3 占比低但伤害大优先修，E1 占比高是长期主线）
- 快评和深检的区别？（快评保吞吐只抓明显错误，深检逐字段核对——所以「对齐 94%」和「通过率 93%」是两个口径）

## 练习三：改 prompt → 跑回归 → 验证提升（约 30 分钟，闭环核心）

**做什么**
1. 「Prompt 实验室」→ 从 baseline fork 一个版本（如 `v2.0-我的调优版`）
2. 先跑一次回归（30 口径，对比基线 `baseline`）记下起点指标
3. 改 T5 工具描述：参考内置 v1.0 的写法，把类目边界规则写进去（腌制未穿串→腌制烤肉类；穿串优先于腌制；仅含烹饪建议词的未加工鲜肉→鲜分割肉类；冷冻未加工→冷冻肉类）
4. 类目知识切换到 `kv-v2`，T6 理由模式改为「模板化」，保存
5. 再跑一次回归（对比 baseline）——看类目对齐准确率、理由一致率的涨跌，以及分错误类型变化

**自测问题**
- 你的改动让哪个指标动了多少？有没有「总体涨了但某类错误暴增」？（回归测试的意义：防「改好一处改坏三处」）
- 为什么 T6 模板化能消灭数值幻觉？（数字从工具返回值占位符填充，模型只组织语言——不给模型犯错的机会，好过要求它不犯错）
- 工具描述的「边界条件」和产品需求文档的「需求边界」是什么关系？（同一件事——agent 时代的工具描述就是产品文案）
