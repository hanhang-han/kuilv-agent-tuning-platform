# 选品 Agent

一个可以对话的选品 Agent：用自然语言提出选品需求（竞对 × 城市 × 品类），Agent 探测数据覆盖、路由识别策略、对齐类目、生成带数据的推荐理由。

```bash
npm install
npm run generate        # 重新生成模拟数据（固定随机种子，可重复）
npm run dev             # http://localhost:3000
```

**配置 API Key（必需）**：复制 `.env.local.example` 为 `.env.local`，填入 DeepSeek API Key（[platform.deepseek.com](https://platform.deepseek.com)）。未配置时页面会显示配置指引。

**测试**：`npx tsx scripts/smoke-test.ts`（无需 API Key，验证工具层与口径解析逻辑）

## 对话能做什么

- **自然语言口径**：「看看竞对A在北京的半熟调理类目有什么高销品」——缺竞对/城市/品类时 Agent 会先澄清，不猜
- **多轮追问**：「那上海呢」「换成调味酱料」——延续上文口径，只替换变化项，直接重跑
- **决策过程透明**：每次工具调用（T1-T6）以可展开的气泡展示输入输出，推荐理由中的数字高亮可追溯
- **解释推荐**：「为什么推荐这个」——基于工具返回数据回答，数据不够会再调工具

## Agent 架构

```
用户自然语言需求
  ↓ Planner（LLM，解析口径，缺项先澄清）
T1 数据覆盖探测 → sales / inventory / none
  ↓ 动态路由
有销量 → T2 销量榜单（top20% 且 ≥200 件）
仅库存 → T3 库存推算（3 天差值：剔除补货、保守累加）
均无   → T4 多因子评分（促销/在售/长期在售/渠道标签加权）
  ↓
T5 商品语义对齐（LLM：脏标题 → 标准类目封闭枚举，边界规则 + few-shot）
  ↓
T6 推荐理由生成（模板化：数字占位符填充，禁止模型编数字）
  ↓
流式回复：自然语言总结 + 推荐清单卡片
```

**核心设计原则**：数值计算全部留在确定性工具里，LLM 只做语义对齐、策略路由和理由组织——幻觉的破坏面被锁死在可校验的语义层。

## 调优

Agent 的六个可调层（工具描述 / 类目知识 / 系统提示词 / 对话指令 / 策略参数 / 理由模板）、已知类目混淆点、验证流程，以及在此之上构建调优平台的需求规格，见 **[docs/调优指南.md](docs/调优指南.md)**。

## 模块对照

| 代码位置 | 职责 |
|----------|------|
| `src/app/page.tsx` | 对话界面（流式消息、工具气泡、推荐卡片） |
| `src/app/api/chat/route.ts` | SSE 流式对话端点 |
| `src/lib/agent/chat-runner.ts` | 多轮 ReAct：口径解析、流式输出、追问上下文 |
| `src/lib/agent/tools/t1~t6.ts` | 六工具实现，T1-T4 确定性计算，T5/T6 内部 LLM 子调用 |
| `src/lib/llm/client.ts` | DeepSeek 客户端（OpenAI 兼容，temperature=0，流式 + 重试） |
| `src/lib/storage/index.ts` | 只读数据层（竞对/类目/知识/商品/Prompt 版本） |
| `scripts/generate-data.ts` | 模拟数据生成 |

## 模拟数据

- 3 个竞对对应三种数据覆盖档位（有销量 / 仅库存 / 均无）→ 三条策略路径
- 428 个商品（脏标题：营销词/规格/emoji 混杂），8 品类 29 个叶子类目，36 个类目边界难点商品（腌制烤肉/烧烤串/鲜肉标题交叉）
- 金标 = 真值销量 top20% 且 ≥200 件（有销量口径的推荐与之一致）
